1. What the module does

The module measures neurites for each cell in live high-content images (for example RGEDI, EGFP fill in the FITC channel). For each well and timepoint it does these steps:

16 raw IXM tiles→ whole-well montage (4×4, 8192×8192 px)→ Cellpose-SAM cell bodies (somas)→ clDice U-Net neurite map→ each neurite assigned to the soma it grows from→ percell.csv + perwell.csv + QC overlay
  • Montage, not tiles. Neurites that cross a tile edge are traced as one piece.
  • Somas: Cellpose-SAM on each raw tile, with a debris filter.
  • Neurites: a small U-Net trained with the clDice loss on 12 hand-traced fields (SNT). On held-out fields it scored F1 0.645, against 0.135 for the old Frangi filter.
  • Attribution: a neurite counts for a soma only if it leaves that soma outward (root-contact rule). A neighbour's neurite that only touches the soma is not counted.
  • Measurements per cell: total neurite length, skeleton pixels, branch points, tips, primary neurites, longest path.
  • Cache: the slow GPU part (somas + neurite map) is saved per well. Later runs with new post-segmentation settings use the cache and need only a CPU.

The full methods text is in docs/METHODS_neurite_quantification.md.

3. One-time setup

3a. Cluster access

  1. Get a cluster account in the finkbeinerlab group, and ScaleFT (sft) on your computer. Ask Gladstone IT.
  2. Enroll once: sft enroll (team gladstone, in your browser). If a command later says “Authentication token expired”, run sft unenroll and then sft enroll again.
  3. Log in to the dev node: sft ssh fb-galaxy-dev01. To run one command without logging in: sft ssh --command '<command>' fb-galaxy-dev01. The remote command must use --command.
The dev node is shared and has no GPU. Use it only to edit files, run git, and submit jobs. Run all real work as a Slurm job (sbatch) on the galaxy partition.

3b. Get the code on the cluster

On fb-galaxy-dev01:

git clone -b austin-claude https://github.com/finkbeiner-lab/nextflow-cluster.git ~/nextflow-cluster
cd ~/nextflow-cluster && git log --oneline -1

Code may live in your cluster home. Outputs may not. Write all outputs to a lab project folder on the HIVE, for example /gladstone/finkbeiner/<PI-or-project>/<your-folder>/. Raw image folders under /gladstone/finkbeiner/robodata/ are read-only: never write there.

3c. Check that you can read the shared files

ls -l /gladstone/finkbeiner/kaye/XDP/dev-nextflow-modules/nextflow-cluster.sif \
      /gladstone/finkbeiner/kaye/XDP/dev-nextflow-modules/neurite-model-runs/run1/best.pt \
      /gladstone/finkbeiner/kaye/XDP/neurite-rework/example-test/

If you get “Permission denied”, ask IT to add you to the finkbeinerlab group.

Both tests pass? Your setup is correct, and you can run your own data.

5. Run the module on your own data

5a. Check that your images fit

  • ImageXpress (IXM) file names with the pattern ..._<TP>_..._<WELL>_<SITE>_FITC_....tif.
  • 16 sites per well in a 4×4 grid, read left to right and top to bottom, with no overlap.
  • The cell-fill (morphology) signal is in the FITC channel. The channel name is fixed in the code.
  • Folder layout <RAW_ROOT>/<raw_folder>/<WELL>/.
  • 20X objective, as in the training data. Other objectives, markers or cell types need a check (see section 10).

A different grid, channel name or file pattern needs a small code change in well_tiles() and GRID in montage_percell.py. Ask Claude to make it, then run the example test again.

5b. Make a manifest

One row per well. One timepoint per row; to measure several timepoints, add one row per (well, timepoint).

experiment,well,timepoint,cell_line,genotype,raw_folder
MYEXP,B02,T5,lineA,CTR,MYEXP-RGEDI
MYEXP,B03,T5,lineB,XDP,MYEXP-RGEDI

cell_line and genotype are only copied to the output. Use any labels. If you leave out raw_folder, the script uses <experiment>-RGEDI. Put the manifest in your lab project folder.

5c. Submit

cd ~/neurite-jobs
sbatch --time=10:00:00 \
  --export=ALL,MANIFEST=/gladstone/finkbeiner/<lab-folder>/<project>/manifest.csv,RAW_ROOT=/gladstone/finkbeiner/robodata/<scope>/<user>,OUT=/gladstone/finkbeiner/<lab-folder>/<project>/neurite,LABEL=first \
  ~/nextflow-cluster/ml/neurite/sbatch/neurite_run.sbatch
  • Time: about 4–5 minutes per well on a V100 GPU. Set --time to that plus margin. If the job runs out of time, submit it again with the same OUT: finished wells come from the cache in about a minute each.
  • Start small. Run 2–4 wells first and look at the overlays before you run a full plate.
  • One well fails? The log shows FAILED or SKIP for that well and the job goes on with the next one. SKIP: found N FITC tiles (need 16) means the files are missing or the names do not match.

5d. Change settings later without the GPU

The cache keeps soma labels and the neurite map. You can change the neurite threshold, --seam-band, --min-neurite, --soma-dilation and the attribution settings (--root-px, --min-radial, --cross-cos) and recompute on a CPU node: same OUT, a new LABEL, DEVICE=cpu, and remove the --gres line. Each run goes to its own folder OUT/runs/<timestamp>_<LABEL>/; earlier runs are never overwritten.

Soma settings (--diameter, --flow, --cellprob, --clean-k, --soma-*), --flatten-size and the checkpoint are saved inside the cache. If you change them, use a new cache folder. The script refuses a cache that was made with different settings.

Cache runs do not write overlays. To make overlays for a cache run (CPU only):

apptainer exec -B /gladstone/finkbeiner:/gladstone/finkbeiner <SIF> \
  python ~/nextflow-cluster/ml/neurite/montage_percell.py --overlay-only --run-id <run id> \
  --manifest <manifest> --raw-root <RAW_ROOT> --out-dir <OUT> --cache-dir <OUT>/cache --checkpoint <CKPT>

Run this inside a Slurm job, not on the dev node.

6. Output files and how to read them

OUT/
  runs/<timestamp>_<label>/
    percell.csv              one row per soma
    perwell.csv              one row per well
    params.json              every setting of this run
    <EXP>_<WELL>_<TP>_percell.tif   QC overlay, 4x downsampled (fresh GPU wells only)
  latest -> runs/<newest>
  cache/<EXP>_<WELL>_<TP>.npz      soma labels + neurite map (keep this)

percell.csv

ColumnMeaning
soma_idSoma label in the montage. Unique only inside one (experiment, well, timepoint).
area_px, cy, cxSoma area and centre (row, column) in montage pixels
neurite_len_pxTotal length of this soma's neurites (straight step = 1, diagonal = √2). 0 = no neurite.
skel_pxNumber of skeleton pixels (the unit CellProfiler uses)
n_branch_points, n_end_pointsBranch nodes and tips on this soma's neurites
n_primary_neuritesNeurites that leave the soma
max_branch_lengthLongest path from the soma along the neurite (px)

perwell.csv

ColumnMeaning
n_somas, n_somas_with_neuriteAll somas; somas with a neurite
total_len_px, mean_len_per_somaSum of lengths; sum divided by all somas (zeros included)
median_len_per_somaUsually 0, because most somas have no neurite. Do not use it for length.
mean_branch_points, mean_tips, mean_primary_neurites, mean_max_branch_len, frac_branchedAverages over somas with a neurite only

How we analysed the XDP data

  • Two readouts (agreed with Julia, October 2026): (1) length and branching among cells that have a neurite (neurite_len_px where skel_px > 0); (2) the fraction of cells with a neurite. The fraction of cells with no neurite changes a lot between experiments for technical reasons, so we did not use mean length over all somas.
  • Replicates: the cell line is the replicate for genotype; wells are not independent. Use a mixed model with experiment and cell line as random effects.
  • Units: pixels. For the IXM 20X objective with 1×1 binning, 1 px ≈ 0.348 µm (XDP1/3/5: 0.347534; XDP8/10/11: 0.348214). Read your own value from the tile metadata (spatial-calibration-x).
  • siRNA or drug is not in the output. Join it from your plate map on (experiment, well).

8. How we ran cluster jobs with Claude

Most of this module was built with Claude Code, an AI coding assistant. This is the way of working that we used. It is safe on a shared cluster.

Who does what

ClaudeYou
Reads code and data (read-only), writes and edits code, writes the .sbatch job script, reads logs and results, makes figures and reports. Submits every job (sbatch), cancels jobs (scancel), approves every write, decides what to delete, pushes code.
Rules we kept Claude never submits or cancels a Slurm job. No heavy work on the dev node. Raw data is read-only. Outputs go to the HIVE, never to the cluster home. Never push to or merge into main; it belongs to the whole lab. Work on your own branch made from austin-claude.

The loop

  1. Tell Claude what you want, for example: “Run the neurite module on wells B02–B12 of MYEXP at T5. The raw data is in <path>. Write outputs to <HIVE folder>.”
  2. Claude checks the input files over sft (read-only), writes the manifest and a self-contained .sbatch script on your computer, and gives you one command to submit it.
  3. You run the submit command. It sends the script to the cluster and submits it: 
    base64 < ~/sbatch-claude/JOB.sbatch | sft ssh --command 'mkdir -p ~/<project> && cd ~/<project> && base64 --decode > JOB.sbatch && sbatch JOB.sbatch' fb-galaxy-dev01
    base64 turns the script into plain text, so it goes through the SSH pipe without quoting problems.
  4. Check the queue (all users, so you can see GPU contention): 
    sft ssh --command 'squeue -o "%.8i %.10u %.14j %.9P %.8T %.10M %.9l %.6D %.10b %R" -S -t,i' fb-galaxy-dev01
  5. When it is done, Claude reads the log and the CSVs over sft and reports the result.

Help for your own Claude sessions

  • CLAUDE.md in the repository root tells Claude the project rules, the cluster setup and this module. Claude Code reads it automatically when you start it in the repository folder.
  • .claude/skills/cluster-batch-submit/ in the repository teaches Claude the submit hand-off above.
  • Good first prompts: “Read docs/neurite_howto.html and CLAUDE.md, then help me run the neurite example test.” “Explain how montage_percell.py assigns a neurite to a soma.”
  • Ask for a plan before large changes. Read every change (git diff). Run the example test again after you change the code.

9. The other route: Nextflow + database module

bin/neurite_montage.py is the same method as a Nextflow pipeline step (DO_NEURITE_MONTAGE = true in the config). It reads tiles from the galaxy database and writes celldata and neuritecelldata rows instead of CSV files. It was tested on XDP5 (job 20554, 2026-09-04). Example config: configs/austin/finkbeiner-neurite-montage-XDP5.config.

cd ~/nextflow-cluster
python bin/validate_config.py <your.config>
sbatch --export=ALL,NEXTFLOW_INSTALL_DIR=$HOME/nextflow-cluster run.sh -c <your.config>
Use the CSV route for results that you compare with the XDP data. The database module does not have the root-contact attribution (--root-px, --cross-cos) or the newer branch metrics, so its numbers are not the same. It also needs an experiment that is registered in the database, and params.platemap_path must list your wells.

10. Limits, known problems, troubleshooting

What we know about accuracy

  • The neurite model was trained on 12 hand-traced fields of live RGEDI (EGFP fill) neurons, 20X, from four XDP experiments. Held-out F1 = 0.645. For a new marker, objective or cell type, look at overlays first, and if possible trace a few fields in SNT and score them (ml/neurite/eval_qa.py). To retrain, see ml/neurite/README.md.
  • Attribution is not perfect. In a check with fake somas (real masks moved to random places), we estimated that 14–24% of “has a neurite” calls are chance contacts in dense wells. Total length per well does not depend on attribution.
  • Live neurite images are faint and change between experiments. Fixed MAP2 staining traces much more cleanly, if your question allows fixed cells.
  • Most somas have no traced neurite, so medians are usually 0.

Troubleshooting

ProblemCause and fix
Job is PENDING (Resources) for hoursThe galaxy partition has only 2 GPU nodes (one V100 each). CPU jobs from other users can fill them. Wait, or ask the other user or IT.
SKIP: found N FITC tiles (need 16)Wrong RAW_ROOT, raw_folder, well or timepoint, or not a 16-tile FITC well.
cache ... built with different paramsYou changed a soma setting or the checkpoint. Use a new cache folder.
Run is about 10× slower than expectedCellpose 4 must use use_bfloat16=False on V100 GPUs. The script already does this; keep it if you edit the code.
refuses to overwriteThe run folder exists. Use a new LABEL, or --overwrite if you are sure.
Bright bands or straight lines along tile edges in the overlayEdge effects of per-tile normalisation. Keep --seam-band 6 and --flatten-size 128.
Permission denied on the SIF or the modelYou are not in the finkbeinerlab group. Ask IT.
Test 1 failsYour checkout is not austin-claude, or the code was changed. Check git -C ~/nextflow-cluster status and the code: line at the top of the log.
